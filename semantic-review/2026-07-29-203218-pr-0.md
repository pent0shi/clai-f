# Explicit background control and resilient streamed tool UI (v2)

This revision makes finite background work opt-in, strengthens provider-stream recovery, and opens native tool cards as soon as tool names arrive. It preserves streamed output across provider failures, binds parallel tool UI state by native call index, refreshes early cards with finalized arguments, and caps model-only recovery loops. The index-to-result mapping, Responder bound, and classic finalized-argument behavior now hold, but interrupted streams can still duplicate prose around an early card. **Watch for:** **confirmed** blocking duplication of pre-tool prose when a provider gives up after opening an early card; **confirmed** missing direct regression coverage for the runner-level stream/retry behaviors.

## High-level view

Native tool streaming now reserves card IDs by provider call index, including placeholders for lower indexes that have not arrived yet. Completion reconciliation reuses those IDs, and execution selects IDs by the bound call index, so out-of-order deltas no longer swap result ownership.

Partial provider output is committed before retry or terminal failure, and any early card that cannot execute is transitioned to blocked. A **confirmed** TUI ordering bug remains: opening the card finalizes the streamed assistant row, after which terminal preservation emits the same pre-tool prose as a new row below the blocked card.

Model-only rounds now share a turn-level counter. Native-tool models switch to the fenced text protocol on the second non-actionable response, unread Responder recovery stops with a partial outcome on the sixth, and any executed tool result resets the counter.

Finite shell work and nmap scans now remain synchronous unless `background` or `responder` is explicitly selected. Provider stream liveness budgets are longer for reasoning requests, while blank SSE traffic no longer counts as progress; no authentication, credential-forwarding, or target-scope boundary changes accompany the transport adjustment.

## Interrupted stream preservation duplicates prose after an early card

The recovery catch now commits partial text to UI/history and marks every shown deferred tool as blocked before a terminal give-up. A **confirmed** ordering bug remains when prose preceded a native tool name: the early `tool-call` event at `src/agent/runner.ts:4334` invokes `closePendingAssistant` at `src/tui-v2/state/transcript-reducer.ts:346`, finalizing that prose above the card; `writeAssistantMessage(partialVisible)` at `src/agent/runner.ts:4479` then appends it again below the card.

```text
assistant "I will inspect."
blocked tool "fs.read"
assistant "I will inspect."
```

The terminal partial-output path should use the same shown-card guard as `commitAssistantRetry`, without dropping the partial history entry or blocked transition.

## Provider-indexed IDs preserve native call ownership and finalized arguments

When index 1 arrives before index 0, the runner reserves a placeholder ID for index 0 and stores the arriving card at index 1. Completion reconciliation reuses each indexed `eventId` (`src/agent/runner.ts:4659-4660`), and execution passes `callIds[bc.index]` into the lifecycle (`src/agent/runner.ts:6171`), retaining index-correct UI/result IDs.

TUI v2 receives a second same-ID card event and updates the existing argument display. The classic path does not print the name-only card during streaming; it flushes `deferred.rendered` only after completion replaces the empty arguments (`src/agent/runner.ts:5785-5789`). A reducer smoke check retained one card, updated its label to `command=echo ok`, and attached the result to that card.

## Runner-level regression scenarios remain untested

A **confirmed** coverage gap remains: none of the changed tests exercises terminal give-up with partial prose and an early card, out-of-order `onToolCallDelta` indexes through tool results, six unread-Responder model-only rounds, or classic output with name-first/final-arguments-later native deltas. The reducer update also lacks a committed same-ID argument-refresh test. Add runner integration cases around the provider callback/event stream; the interruption case should assert one prose row followed by one blocked card.
